用户明确要求：速度估计器必须用 GFG，GFG 与后续模块联合训练；先确定最可能的优势场景，完成必要小实验、修复问题，再全量训练。此指令覆盖之前的 VeloVI 替代路线和“动力学编码器 A 后全部冻结”的实现假设。

## 主张与判决边界

优势假设是：静态表达相近、动态状态不同，且未来响应组分比例或路径在新群体中发生变化时，GFG velocity 可以帮助 router 改善分布预测。多专家、低熵、重构下降或真值监督的合成归属准确率，均不能单独构成该主张的证据。

不保证得到阳性；不按结果选择开发 TF、修改阈值或删除失败。开发集已多次查看，后续均标探索性。最终 5 个确认 TF 继续封存。现有负结果仅对应简单残差 velocity，不是 GFG 的检验。

## 顺序

1. GFG 资产与数值验收：使用实际 RNA 双流 + 解码器 JVP，严格加载、权重/源码哈希、源输入与预训练清单审计，验证无 c 前向入口及路由损失能反传到 GFG。不得把旧 MLP 改名为 GFG。
2. 真实多峰审计：仅使用训练 TF；按条件内部拆分 discovery/validation，模式规则由 discovery 冻结；检查独立细胞子集与两条 guide 的复现。KMeans 两簇只是候选，不是多峰判据。
3. 优势场景合成实验：已知真值，但正常训练不读取逐细胞真值模式；区分固定 50:50 的边际不可辨识、组分比例变化、位置决定模式和单峰负对照。真值 velocity/真值模式臂只作明确标注的能力参照，不冒充 GFG 成果。
4. GFG 小预算联合训练及真实静态/置换对照。保留表达专家与条件通道的匹配预算；主任务梯度通过 velocity/router 更新 GFG，同时保留原生重构/JVP/动力学约束，记录任务与原生梯度、速度塌缩和偏离。
5. 只有工程验收通过，且开发侧实际分布增益同时胜过静态与置换、没有不可解释的整体退化，才扩大到全量训练。真实多峰/增量未成立则如实记录，先限定一次有依据的修复或时间锚检查，不自动长训。

GFG 自身允许短暂热身，不允许把热身后永久冻结作为主方法；冻结版本只能作消融。E-step、老师标签、参考库构建仍 stop-gradient，门控校准不反向牵动 GFG；`c` 不直接作为 GFG 的前向输入。训练任务梯度可以依赖 c，这不等于把 c 接进编码器输入。
